## 二、实现上仍缺的部分

- [ ] **HTTP/SSE 门面**（P4-1 / P4-3 的原字面口径）

  当前形态是 CLI 直连 Redis / PG，`GET /sessions/{sid}/events` 与
  `GET /sessions/{sid}/messages?since=&limit=` 两个 HTTP 端点不存在；
  它们的语义已分别由 `MessageSubscriber`（无位置参数、全量重放）与
  `HistorySource.since`（按 msgSeq 分页、过滤 superseded）以接口形式交付。
  接 HTTP 时只需把这两个接口挂到路由上，**不允许在门面里加位置参数解析** ——
  那会把 P4-1 删掉的续传定位逻辑又养回来。
  完成标准：两个端点存在且 `Last-Event-ID` 被证明不影响重放起点。

- [ ] **`markSuperseded` 的生产调用方**（P4-5 的后半）

  存储层（列、`since` 过滤、`markSuperseded`）已就绪且有真库测试；
  写入方是 P5-10（turn 重跑清理，接管方标记 `supersededReplyId`）。
  在那之前 `superseded` 恒为 false，过滤逻辑空转但无害。
  完成标准：P5-10 落地时连同重跑测试一起交付。

- [ ] **重连期间 `/stop` 的行为说明**

  断线时控制指令仍可投递（inbox 不依赖订阅连接），但控制帧的回执要等重连后才可见，
  状态条会多挂一会儿"已发出"。行为正确但缺一条用户可见的说明。
  完成标准：`docs/客户端协议.md` 补一句断线期间控制指令的回执时序。
