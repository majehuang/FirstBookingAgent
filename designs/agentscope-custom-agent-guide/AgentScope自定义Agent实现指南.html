01 / EXECUTIVE SUMMARY四个实现结论

01

Agent 启动不等于加载会话

构造期只固定模型、Prompt、Toolkit、中间件、Workspace 与 Store；真正的 AgentState 在每次 call 入口按会话加载。

02

上下文每轮动态装配

最终模型输入由系统提示、工作区注入、会话历史/摘要、当前输入和可用 Tool Schema 组成，不是一段固定字符串。

03

事件流不等于客户端消息流

模型与工具事件先进入应用适配器；只有文本块、受支持的数据块和表达型 Tool 的成功结果才生成用户可见消息。

04

富消息以工具最终结果为准

TOOL_CALL_END 没有完整入参；卡片载荷必须在 Tool 或 Middleware 中补全并冻结，成功结束后再持久化和推送。

框架事实与项目约定

Agent Loop、AgentState、事件字段和 Tool 执行机制来自 AgentScope Java 2 源码；“Ctrl 指令 / 用户可见消息指令”的映射是本文为当前分布式消息方案定义的应用层路由约定，并非 AgentScope 内置协议。

02 / AGENT LOOP完整生命周期：加载、推理、行动、暂停与保存

同一 (userId, sessionId) 的调用由框架串行化，不同会话可以并行。call() 与 streamEvents() 走同一条内部执行链；前者只筛出最终 AgentResultEvent，后者暴露全过程事件。

持久化语义

AgentState 是在一次 call / streamEvents 结束时整体保存，不是每产生一个 block 就写一次 Store。分布式故障恢复仍需要应用层 lease、输入幂等和消息真相源来覆盖“执行中进程崩溃”的窗口。

03 / CONTEXT ASSEMBLYAgent 从哪里加载上下文

要区分三种时间：JVM 构造期加载静态能力；每次调用入口加载会话状态；每次 Reasoning Round 再动态拼装模型真正看到的上下文。

05 / EVENT ROUTING哪些事件生成 Ctrl，哪些生成用户可见消息

适配器把同一条 AgentEvent 流分成三条语义不同的输出：瞬时 Ctrl 状态、持久化用户消息、诊断日志。路由必须集中在一个单写者中，避免并发 Tool 和 Text 破坏消息顺序。

事件Ctrl用户消息仅日志建议处理
AGENT_START●—○turnActive=true，锁定输入，记录 activeReplyId
MODEL_CALL_START / END●—●phase=reasoning；End 记录 token usage
TEXT_BLOCK_START○—○初始化 (replyId, blockId) 缓冲区

THINKING_BLOCK_*——●默认不透出思考；只用于受控可观测性

TOOL_CALL_START●—●phase=acting，显示可选的“正在查询”进度

ToolCall End 的边界

源码中的 ToolCallEndEvent 只有 replyId / toolCallId / toolCallName。如果业务需要完整 JSON 入参，应累计 ToolCallDelta，或更稳妥地在 onActing Middleware / Tool 内取得已解析参数。富消息一定等待 Tool 成功和载荷冻结后再发。

Delta Text Block 的正确处理

STEP 01 · CORRELATE

按 block 建缓冲区

Start 创建缓冲区；Delta 按 (replyId, blockId) 追加。不要把同一 reply 中多个块拼错。

STEP 02 · COALESCE

合并小碎片

以时间或字节阈值批量生成 append 指令，降低 DB/outbox 写放大，同时保持实时感。

STEP 03 · COMMIT

End 强制 flush

对当前逻辑消息落最终内容和完成状态；客户端以 instructionId 幂等，断线后可重放。

// 应用层伪代码：ClientInstruction / MessageWriter 为本项目类型
switch (event.getType()) {
  case TEXT_BLOCK_START -> textBuffer.open(replyId, blockId);
  case TEXT_BLOCK_DELTA -> textBuffer.append(replyId, blockId, event.getDelta());
  case TEXT_BLOCK_END -> messageWriter.commit(textBuffer.flush(replyId, blockId));
  case AGENT_END -> ctrlWriter.publish(CtrlState.idle(sessionId));
  default -> diagnostics.append(event);
}

06 / CUSTOM TOOLS自定义 Tool：一个执行协议，两种业务语义

所有 Tool 都把“模型的 JSON 参数”转换为 Mono<ToolResultBlock>。Toolkit 负责向模型暴露 JSON Schema、解析 ToolUseBlock、执行权限检查，并通过基础设施层统一调度、超时、重试和异常转换。

公共实现约束

SCHEMA FIRST
工具名用 snake_case；description 明确“何时调用、返回什么”；输入严格采用 JSON Schema，并限制数组大小和字符串长度。
REACTIVE RESULT
显式 Tool 实现 AgentTool 或继承 ToolBase，统一返回 Mono<ToolResultBlock>；业务错误转换为可理解的 ToolResult。
PERMISSION
纯查询标记 readOnly=true；只有线程安全、无共享可变状态的工具标记 concurrencySafe=true。
SMALL OBSERVATION
给 LLM 的 output 要精简；大对象、UI 载荷和审计字段放 metadata 或业务存储，避免污染后续上下文。

07 / DATA TOOL第一类：调用外部接口获取数据

这种 Tool 是“认知型 Tool”：为模型补充事实，结果回到 Agent Loop 的下一轮推理，默认不直接生成客户端消息。它应隔离外部协议，把响应规范化成稳定、小型的领域 DTO。

01 · VALIDATE

校验模型入参

把 Map 转换为 Java 21 record；校验城市、日期、页大小等业务不变量，拒绝模糊或过大的请求。

02 · FETCH

调用 Gateway

通过 Reactor Gateway 请求外部 API，配置超时、有限重试、熔断和 traceId；敏感 header 不进入 ToolResult。

03 · NORMALIZE

形成精简观察

去除供应商字段，把结果转为摘要 JSON；保留 source、dataAsOf 和结果数量用于解释与审计。

public final class SearchHotelsTool extends ToolBase {
  private final HotelGateway gateway;
  private final ObjectMapper mapper;

  public SearchHotelsTool(HotelGateway gateway, ObjectMapper mapper) {
    super(ToolBase.builder()
        .name("search_hotels")
        .description("按城市和入住日期查询实时酒店候选；需要事实数据时调用")
        .inputSchema(Map.of(
            "type", "object",
            "properties", Map.of(
                "city", Map.of("type", "string"),
                "checkIn", Map.of("type", "string", "format", "date"),
                "limit", Map.of("type", "integer", "minimum", 1, "maximum", 10)),
            "required", List.of("city", "checkIn")))
        .readOnly(true)
        .concurrencySafe(true)
        .build());
    this.gateway = gateway;
    this.mapper = mapper;
  }

  @Override
  public Mono<ToolResultBlock> callAsync(ToolCallParam param) {
    var query = mapper.convertValue(param.getInput(), HotelQuery.class);
    return gateway.search(query)
        .timeout(Duration.ofSeconds(3))
        .map(result -> ToolResultBlock.builder()
            .output(List.of(TextBlock.builder()
                .text(mapper.valueToTree(result.forModel()).toString())
                .build()))
            .metadata(Map.of(
                "source", result.source(),
                "dataAsOf", result.dataAsOf().toString(),
                "resultCount", result.items().size()))
            .build());
  }
}

record HotelQuery(String city, LocalDate checkIn, int limit) {}
错误策略

网络超时、4xx/5xx 和供应商限流应转换成可供模型恢复的简短错误观察，例如“服务暂不可用，可缩小范围后重试”，同时把原始异常和响应体留在日志链路，不要直接暴露给用户或模型。

08 / PRESENTATION TOOL第二类：生成特定格式消息

这种 Tool 是“表达型 Tool”：模型决定展示哪种消息，Tool 负责补全、校验并冻结客户端协议。最终 ToolResultBlock 只给 LLM 一段短确认，完整 UI 载荷放入 metadata，由事件适配器转成一条可持久化富消息。

public final class SendHotelCardsTool extends ToolBase {
  private final CardCompletionService completion;
  private final ObjectMapper mapper;

  public SendHotelCardsTool(CardCompletionService completion, ObjectMapper mapper) {
    super(ToolBase.builder()
        .name("send_hotel_cards")
        .description("向用户展示酒店卡片；候选已确定且需要结构化呈现时调用")
        .inputSchema(HotelCardSchema.INPUT)
        .readOnly(true)
        .concurrencySafe(true)
        .build());
    this.completion = completion;
    this.mapper = mapper;
  }

  @Override
  public Mono<ToolResultBlock> callAsync(ToolCallParam param) {
    var intent = mapper.convertValue(param.getInput(), HotelCardsIntent.class);
    return completion.completeAndFreeze(intent, param.getRuntimeContext())
        .map(payload -> ToolResultBlock.builder()
            .output(List.of(TextBlock.builder()
                .text("已向用户展示 %d 家酒店".formatted(payload.items().size()))
                .build()))
            .metadata(Map.of(
                "clientMessageType", "hotel_cards.v1",
                "clientMessageId", payload.messageId(),
                "clientPayload", payload,
                "dataAsOf", payload.dataAsOf().toString()))
            .build());
  }
}

为什么不在 TOOL_CALL_END 直接发卡片

该事件既没有完整参数，也不能证明 Tool 已执行成功，更不知道 Tool 是否已经补全缺失字段。正确时机是：Tool 内生成冻结 payload → 适配器按 toolCallId 关联 → TOOL_RESULT_END(SUCCESS) 后一次性持久化并推送。

09 / ASSEMBLYAgent 组装与调用示例

生产环境优先用 DistributedStore 一键注入分布式 AgentState 与工作区后端；应用级 Tool 注册到同一 Toolkit，事件适配器订阅 streamEvents()。

var toolkit = new Toolkit();
toolkit.registerTool(new SearchHotelsTool(hotelGateway, objectMapper));
toolkit.registerTool(new SendHotelCardsTool(cardCompletion, objectMapper));

DistributedStore store = RedisDistributedStore.fromJedis(jedis);

HarnessAgent agent = HarnessAgent.builder()
    .name("travel_assistant")
    .sysPrompt("你是企业差旅助手；先查事实，再选择合适的消息格式表达。")
    .model("dashscope:qwen-plus")
    .workspace(Path.of(".agentscope/workspace"))
    .toolkit(toolkit)
    .distributedStore(store)
    .middleware(new ClientMessageCaptureMiddleware(richPayloadStore))
    .build();

RuntimeContext rc = RuntimeContext.builder()
    .userId(userId)
    .sessionId(sessionId)
    .put(RequestTrace.class, trace)
    .build();

Flux<AgentEvent> events = agent.streamEvents(new UserMessage(text), rc);
return eventAdapter.route(events); // ctrl / message / diagnostics

10 / ACCEPTANCE实现与验收清单

STATE
相同会话跨 pod 能恢复 AgentState；相同会话并发请求被串行；不同会话可并行。
CONTEXT
能从观测中确认 system prompt、摘要、保留历史、Tool Schema 与 Workspace 注入的版本。
TEXT
Delta 乱序/重复测试、End flush、SSE 断线重放和 instructionId 幂等全部通过。
CTRL
Start、reasoning、acting、waiting、stopping、idle 状态机无跳变死锁，AgentEnd 始终收敛。
DATA TOOL
超时、限流、供应商错误被规范化；大响应不会直接进入 AgentState；密钥和原始响应不泄露。
RICH TOOL
Tool 失败不展示半成品；成功只生成一条冻结消息；历史重放不重新查询动态数据。
HITL
RequireUserConfirm / ExternalExecution 可暂停、持久化待办并由后续结果事件恢复。
COMPATIBILITY
未知 CUSTOM / 新增枚举默认进入诊断日志，核心链路不因版本增加事件而中断。
