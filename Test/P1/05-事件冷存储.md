# P1 事件冷存储测试用例

## 基本写入

### COLD-001　每个 AgentEvent 都进入冷存储旁路

- 优先级：P0；层级：集成。
- 步骤：让可控 Agent 依次产生文本、工具和结束类事件。
- 预期：每个原始事件都有一条可关联的日志，至少包含正确 `userId/sessionId/replyId/eventType/payload/createdAt`；冷存储记录不替代用户消息表。

### COLD-002　冷存储失败不使 turn 失败

- 优先级：P0；层级：故障注入；覆盖 INV-5。
- 步骤：令 ColdStorageWriter 对所有写入抛错，再执行完整 turn。
- 预期：Agent 流继续，用户消息正常落库并进入 outbox/SSE，turn 可完成；冷存储错误被记录和计量，但不回传为用户回复失败。

### COLD-003　慢冷存储不阻塞实时消息链路

- 优先级：P0；层级：时延集成。
- 步骤：让每次冷存储写入阻塞 1 秒，同时 Agent 以 10～20 次/秒产生文本更新。
- 预期：SSE 更新频率不被拖到 1 次/秒；冷存储工作在独立调度/队列上；turn 主链路不等待冷存储完成。

### COLD-004　冷存储局部失败不停止后续事件记录

- 优先级：P1；层级：故障注入。
- 步骤：只让第 2 条事件写入失败，共产生 5 条事件。
- 预期：第 3～5 条仍尝试写入；主链路完整完成；失败项有独立错误记录，不能让旁路 Flux 被一次异常永久终止。

### COLD-005　不同 session 的事件关联信息不串扰

- 优先级：P1；层级：并发集成。
- 步骤：两个 session 并发产生事件并交错完成。
- 预期：所有日志均可按 session/reply 正确归属；同一事件不会重复归入另一个 session。

### COLD-006　在线流程不读取冷存储

- 优先级：P1；层级：架构测试。
- 步骤：使用一个任何 read 调用都会失败的冷存储 Fake，完成 POST、Worker、SSE 和刷新窗口重放。
- 预期：所有在线功能正常；生产模块不存在从事件日志恢复状态、历史消息或 outbox 的调用。
