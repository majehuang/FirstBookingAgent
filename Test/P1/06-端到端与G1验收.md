# P1 端到端与 G1 验收用例

## 自动化端到端

### E2E-001　单条消息跑通完整链路

- 优先级：P0。
- 环境：真实 Redis 7.0、真实 PostgreSQL、可控 `TurnEngine`。
- 步骤：建立 SSE；POST“你好”；Agent 固定产生 `你`、`好` 和结束事件；等待 turn 完成。
- 预期：POST 在 Agent 完成前返回 `202`；inbox→ready→lease→drain 均发生；SSE 先收到 USER 消息，再收到有序 ASSISTANT 消息；数据库与 outbox 内容一致；`msgSeq` 从 1 开始严格递增无洞。

### E2E-002　同一 session 连续多轮对话

- 优先级：P0。
- 步骤：顺序进行至少 3 轮，每轮等待完成后再提交下一轮；Agent 记录收到的 session 上下文。
- 预期：三轮使用同一 session 状态；每条 USER 和 ASSISTANT 消息顺序正确；replyId 按 turn 区分；全会话 `msgSeq` 单调无洞。

### E2E-003　页面刷新后在 outbox 窗口内续上

- 优先级：P0。
- 步骤：第一轮完成后断开 SSE，模拟清空页面内存并重新连接。
- 预期：新连接从窗口起点收到完整重放；客户端应用去重后得到与刷新前逐字节一致的会话内容；随后第二轮实时消息能继续追加。

### E2E-004　同一用户两个 session 隔离

- 优先级：P0。
- 步骤：交错向 session A/B 各完成两轮并分别连接 SSE。
- 预期：两边上下文、replyId、消息表、Redis key、SSE 和 `msgSeq` 独立；A 的内容不出现在 B。

### E2E-005　ready 写失败后的客户端重试自愈

- 优先级：P0；覆盖 INV-1。
- 步骤：第一次请求在 inbox 成功后注入 ready 写失败；客户端保留原 `instructionId` 重试；恢复 Redis。
- 预期：第一次不是 `202`；第二次成功；最终只有一条 USER 消息和一次 Agent 回复；无重复回复、无 `msgSeq` 空洞。

### E2E-006　大批流事件保持顺序

- 优先级：P0；覆盖 INV-8。
- 步骤：Agent 快速产生至少 1000 个带序号文本片段，并在持久化层注入随机延迟。
- 预期：合并后的最终文本与源文本逐字节一致；消息表、outbox、SSE 的相对顺序一致；连续运行 20 次无偶发乱序。

### E2E-007　冷存储不可用时完整对话仍成功

- 优先级：P0；覆盖 INV-5。
- 步骤：关闭或故障化冷存储，再完成一轮对话和一次刷新重连。
- 预期：POST、Agent、数据库、outbox、SSE 与窗口内重放全部正常；可观测系统记录冷存储失败。

## 流畅度与人工验收

### PERF-001　文本更新频率达到 10～20 次/秒

- 优先级：P0。
- 环境：真实 Redis/PostgreSQL；先使用可控 Agent，再用真实模型复核。
- 步骤：持续输出至少 10 秒，记录每个 SSE 数据帧到达时间和最终文本。
- 预期：稳定输出阶段每秒可见更新在 10～20 次目标区间；不出现超过 1 秒的非模型原因停顿；最终文本无缺字、重字和乱序。
- 说明：`bufferTimeout(64, 80ms)` 的理论定时上限约 12.5 批/秒；“20 次/秒”只能由数量阈值提前触发或按产品口径统计。验收报告必须写明统计口径。

### PERF-002　POST 延迟不受慢 Agent 影响

- 优先级：P0。
- 步骤：分别让 Agent 延迟 0、5、30 秒完成，每档提交至少 30 次独立 session 请求。
- 预期：HTTP Ack 延迟分布不随 Agent 完成时间线性增长；所有 Ack 都在 turn 结束前返回。具体 P95 阈值应由接口 SLA 冻结后补入。
