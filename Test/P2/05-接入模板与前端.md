# P2 富消息接入模板与前端测试用例

## 一种富消息 = 一个 tool + 一个 middleware

### TPL-001　模板包含完整扩展点

- 优先级：P0；层级：模板验收。
- 预期：模板至少包含工具 Schema、工具实现、middleware 补全、render 分支、协议 payload、fallbackText、单测和接入文档。

### TPL-002　新增示例类型无需修改任务调度层

- 优先级：P0；层级：架构测试。
- 步骤：按模板新增一个最小示例富消息。
- 预期：不修改 ready、inbox、lease、cursor、Worker 调度和 Redis key；只扩展 Agent/消息渲染相关包。

### TPL-003　新增类型仍走统一 OutboxWriter

- 优先级：P0；层级：集成。
- 预期：示例消息先落消息表再进入 outbox；没有第二个写入者。

### TPL-004　模板强制 fallbackText 与数据版本字段

- 优先级：P0；层级：静态/模板测试。
- 预期：缺失 fallbackText 无法通过模板测试；带时效数据的类型必须提供 `dataAsOf` 或等价字段。

### TPL-005　模板包含能力协商降级用例

- 优先级：P1；层级：模板测试。
- 预期：支持类型的客户端收到结构消息；不支持的客户端收到 TEXT；序号和 reply 归属不变。

### TPL-006　接入文档可由未参与 P2 的开发者独立完成

- 优先级：P1；层级：文档走查。
- 步骤：让未参与实现的开发者按文档新增示例类型并运行测试。
- 预期：无需口头补充即可完成；文档包含文件位置、命名、线程模型、冻结、降级和测试清单。

## 客户端卡片 UI

### UI-001　完整 CARD 显示标题与三项酒店

- 优先级：P0；层级：组件测试。
- 预期：标题、三家酒店及各展示字段按 payload 顺序呈现。

### UI-002　明确显示“数据截至 …”

- 优先级：P0；层级：组件/快照测试。
- 步骤：输入固定 `dataAsOf=2026-08-24 10:00`。
- 预期：可见文本包含完整“数据截至 2026-08-24 10:00”，不能只藏在 tooltip 或无障碍属性中。

### UI-003　缺失数据时间时不伪装实时数据

- 优先级：P0；层级：异常载荷测试。
- 步骤：输入缺 dataAsOf 的历史卡片。
- 预期：显示明确的未知/缺失提示或 fallback，不显示“实时”“当前价”等误导文案。

### UI-004　畸形 CARD 降级为 fallbackText

- 优先级：P0；层级：组件健壮性。
- 数据：空 payload、items 非数组、未知字段版本、单项损坏。
- 预期：组件不崩溃、不影响后续消息；至少显示 fallbackText。

### UI-005　文本尾巴在卡片前落地

- 优先级：P0；层级：组件集成。
- 步骤：模拟 TEXT_DELTA 后立即到达 CARD。
- 预期：视觉顺序为完整推荐理由、卡片，而不是卡片插入未完成句子。

### UI-006　不支持 CARD 时显示服务端降级文本

- 优先级：P0；层级：协议联调。
- 预期：客户端无需理解 CARD payload；按普通 TEXT 显示 fallbackText，不出现空组件。

### UI-007　可访问性和窄屏不丢关键数据

- 优先级：P1；层级：UI 测试。
- 预期：酒店名称、价格和数据时间可被辅助技术读取；窄屏换行不改变条目顺序，不截掉数据时间。
