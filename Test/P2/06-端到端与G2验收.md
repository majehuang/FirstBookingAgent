# P2 端到端与 G2 验收用例

## 酒店推荐主场景

### E2E-001　表达型工具生成三张完整卡片

- 优先级：P0。
- 环境：真实 PostgreSQL、Redis 7.0、脚本化 Agent、固定酒店服务 Fake。
- 步骤：用户询问酒店；Agent 调用 `send_hotel_cards`；Fake 返回三家固定酒店。
- 预期：产生且只产生一个 CARD 消息组件，payload 正好含三项完整酒店和固定数据时间。

### E2E-002　推荐理由、卡片、追问严格有序

- 优先级：P0；覆盖 INV-8。
- 步骤：执行标准酒店剧本并记录所有消息。
- 预期：用户可见顺序严格为“推荐理由 → 三张卡片组件 → 一句追问”；按 msgSeq 检查，不能只检查最终页面位置。

### E2E-003　工具调用与 shown 支持模型续接

- 优先级：P0。
- 步骤：让模型在工具返回后依据 shown 生成追问。
- 预期：追问引用已展示内容；不再次输出相同卡片；shown 数量与 CARD items 一致。

### E2E-004　关闭页面重开内容逐字节一致

- 优先级：P0；G2 核心门禁。
- 步骤：保存首次 CARD SSE data 原始字节；关闭客户端并重新打开同一会话。
- 预期：重放/历史重建后的 CARD 字节完全相同；酒店服务调用次数不增加。

### E2E-005　酒店价格变化不污染历史

- 优先级：P0。
- 步骤：首次生成后修改 Fake 服务价格和评分，再重开旧会话并创建一个新会话。
- 预期：旧会话仍是旧数据；新会话使用新数据；两者分别显示各自数据时间。

### E2E-006　多次并发运行不出现文本卡片错位

- 优先级：P0；覆盖 INV-8。
- 步骤：至少 20 个 session 并发执行酒店剧本，在补全和持久化中注入随机延迟。
- 预期：每个 session 均保持理由→卡片→追问；CARD 不串 session/reply，msgSeq 各自连续。

## 降级与失败

### E2E-007　不支持 CARD 的客户端收到完整文本

- 优先级：P0。
- 步骤：同一场景分别用支持 CARD 和仅支持 TEXT 的能力连接。
- 预期：前者收到结构卡片；后者收到包含三家酒店关键信息的 fallbackText；两边 msgSeq/replyId/role 对齐。

### E2E-008　补全服务失败不产生半成品卡片

- 优先级：P0。
- 步骤：让酒店服务超时或第三项查询失败。
- 预期：按冻结策略输出可读错误/降级文本；数据库、outbox 和 UI 均无缺字段 CARD；其他 session 不受影响。
