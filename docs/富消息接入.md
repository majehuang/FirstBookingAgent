# 接入一种新的富消息

> 三件东西同时交付，缺一不可。照着 `agent-tools/hotel` 抄即可。

## 为什么是三件

**一种富消息 = 一个表达型工具 + 一个补全 middleware + 一个渲染器。**

少任何一件都不成立：

| 缺 | 后果 |
|---|---|
| 工具 | 模型没有办法表达这种消息 |
| middleware | 卡片里的数据是模型编的 —— 它会一本正经地给出错误的价格 |
| 渲染器 | 用户看到的是一行「⚒ 调用了发卡片的函数」，而不是卡片 |

所以它们用一个 `ToolBundle` 装在一起交付，接入时不会漏掉其中一环。

## 为什么富消息来自工具入参

不是解析模型的自由文本，也不是让模型输出消息 JSON。

函数调用是模型受训行为，schema 即契约。让模型直接吐 JSON 会：
丧失流式体验、拉低文本质量、要处理转义地狱，而且改协议就得改 prompt。

## 四步

### 1. 表达型工具

```java
public final class XxxCardTool {

    @Tool(name = "send_xxx_cards", description = "把…展示给用户。用它来「给用户看」，不要在正文里罗列明细。")
    public Map<String, Object> sendXxxCards(
            @ToolParam(name = "title", description = "…") String title,
            @ToolParam(name = "ids", description = "…") List<String> ids,
            @ToolParam(name = "resolved", required = false, description = "服务端填充，模型不要提供")
            List<Map<String, Object>> resolved,
            @ToolParam(name = "dataAsOf", required = false, description = "服务端填充，模型不要提供")
            String dataAsOf) {

        Map<String, Object> result = new LinkedHashMap<>();
        result.put("shown", "已向用户展示 N 张卡片：…");   // ← 模型靠它续接
        result.put("card", Map.of("title", …, "items", …, "dataAsOf", …));
        return result;
    }
}
```

两个约定：

- **返回值必须带 `shown`。**模型需要知道"我刚给用户看了什么"，才能接着说"这几个里我更推荐…"。
  没有它，模型往往会把明细在正文里再抄一遍。
- **`resolved` / `dataAsOf` 标注「服务端填充」。**模型即使填了也会被 middleware 覆盖。
  用 `LinkedHashMap` 而不是 `Map.of` 构造卡片内容 —— 字段顺序影响序列化结果，
  而卡片要**逐字节**可比对。

### 2. 补全 middleware

```java
public final class XxxEnrichmentMiddleware implements MiddlewareBase {

    @Override
    public Flux<AgentEvent> onActing(Agent agent, RuntimeContext ctx, ActingInput input,
                                     Function<ActingInput, Flux<AgentEvent>> next) {
        if (!needsEnrichment(input)) {
            return next.apply(input);           // 无关调用原样放行
        }
        return Mono.fromCallable(() -> enrich(input))
                .subscribeOn(Schedulers.boundedElastic())   // ★ INV-7，不能删
                .flatMapMany(next);
    }
}
```

**两个坑，两个都是实跑才暴露的：**

> **① `subscribeOn(boundedElastic)` 不能删（INV-7）。**
> 业务数据源是阻塞的，而 middleware 跑在事件循环线程上。少了这一行，
> 一次查询就占住事件循环，**全 pod 所有 session 一起卡**。
> 症状是吞吐莫名掉到个位数，现场根本不指向 middleware。
> `BlockingCallIsolationTest` 用 BlockHound 守着它，并附了反证——去掉 offload 后那条断言确实会红。
>
> 注意工具内部**不**需要这样做：`ToolExecutor` 已经默认跑在 boundedElastic 上。

> **② 重建 `ToolUseBlock` 时必须同时重建 `content`。**
> 它有两份入参：结构化的 `input`，和模型原始的 JSON 串 `content`。
> **参数校验与实际绑定走的是 `content`** —— 只改 `input` 的话补全根本送不到工具，
> 而三参构造器会把 `content` 置空，直接报 `argument "content" is null`。
> 这一点在方法签名上完全看不出来。
>
> ```java
> return new ToolUseBlock(call.getId(), call.getName(), arguments,
>         Json.write(arguments), call.getMetadata());
> ```

### 3. 渲染器

```java
public final class XxxCardRenderer implements RichMessageRenderer {

    @Override public String toolName() { return "send_xxx_cards"; }

    @Override
    public MessageDraft render(String blockKey, Map<String, Object> toolResult) {
        Object card = toolResult.get("card");
        if (!(card instanceof Map<?, ?> map)) {
            return null;                        // 渲染不了就返回 null，调用方会降级
        }
        return new MessageDraft(blockKey, MessageType.CARD, fallbackText(map), (Map) map);
    }
}
```

- **必须是纯函数。**渲染在生成时只跑一次，结果冻结落库，重开会话直接读库 ——
  这里查库就会让"重开会话所见即当时所见"不成立。
- **`fallbackText` 不能为空**，协议层会直接拒绝。客户端不支持这种卡片时它是唯一剩下的东西，
  所以要自己就说得清楚，不能是「[卡片]」这种占位符。
- **返回 `null` 表示放弃**，`EventMapper` 会退回普通工具结果展示。绝不抛异常 ——
  一条渲染不了的卡片不该中断整轮对话。

### 4. 装配

```java
public static ToolBundle of(XxxSource source) {
    Toolkit toolkit = new Toolkit();
    toolkit.registerTool(new XxxCardTool(source));
    return new ToolBundle(toolkit,
            List.of(new XxxEnrichmentMiddleware(source)),
            RichMessageRegistry.of(new XxxCardRenderer()));
}
```

然后在 `EngineOptions` 的 `--tools` 里加一档。

## 界面上会发生什么

注册为表达型工具之后，`EventMapper` 的行为分叉：

| 事件 | 普通工具 | 表达型工具 |
|---|---|---|
| 工具调用 | `⚒ search_hotels()` 状态行 | **抑制** —— 用户该看到卡片，不是"正在调用发卡片的函数" |
| 工具结果 | `✓ search_hotels 返回 4 条` | **渲染成卡片消息** |

工具返回的大段 JSON 在界面上会被压成一行（认得出 `shown` / `count` 就用它们，否则截断）。
**压缩只影响展示** —— 模型拿到的仍是完整返回值，渲染读的也是原始输出。

## UI 必须标注数据时间

卡片内容在生成时就冻结了，之后永远不变。所以 UI **必须**显示 `dataAsOf` ——
否则用户会把三天前的房价当成今天的。终端渲染成：

```
┌ 北京 4 家可选酒店
│ 1. 北京国贸大酒店  ¥1,280  4.8★  含双早
└ 数据截至 2026-08-24 10:00
```

## 验收

```bash
./bin/agent worker --engine agentscope --tools hotel --provider openai --model … &
./bin/agent --session s-1
> 北京有哪些酒店？展示给我看，再说说推荐哪家
```

三条：卡片与文本按正确顺序到达；重开会话卡片内容**逐字节一致**且不重查；
`mvn verify` 中 BlockHound 零告警。
