## 4. 单进程多轮对话

```bash
export AGENT_API_KEY=...
SID="g0-$(date +%H%M%S)"
printf '我叫马工，记住这个名字\n用一句话说明什么是乐观锁\n/quit\n' | ./bin/agent \
    --backend agentscope --provider openai --model kimi-for-coding \
    --base-url https://api.kimi.com/coding --plain \
    --db-user admin --jdbc-url jdbc:postgresql://localhost:5432/agent --session "$SID"
```

**判定**：两轮均有流式回复；第一轮触发 `memory_save` 工具并成功。

**本次结果**：✅

```
› 我叫马工，记住这个名字
⚒ memory_save()
✓ "Saved 1 memory to MEMORY.md"
好的，马工，我已经记住您的名字了。

› 用一句话说明什么是乐观锁
乐观锁是一种并发控制机制，它假设数据冲突很少发生……
```

## 5. 重启后同一 (userId, sessionId) 继续对话

用**同一个 `--session`** 重新起进程：

```bash
printf '我刚才告诉你我叫什么？\n/quit\n' | ./bin/agent \
    --backend agentscope --provider openai --model kimi-for-coding \
    --base-url https://api.kimi.com/coding --plain \
    --db-user admin --jdbc-url jdbc:postgresql://localhost:5432/agent --session "$SID"
```

**判定**：
1. 历史（含用户自己发的话）先于新输入渲染
2. 模型记得上一进程的上下文

**本次结果**：✅ 回答 `您刚才告诉我您叫**马工**。`

恢复是框架自动的 —— 没有为此写任何恢复代码，AgentState 由 PG 版 `AgentStateStore` 承载。

### 数据证据

```sql
SELECT count(*), min(msg_seq), max(msg_seq),
       (max(msg_seq) - min(msg_seq) + 1 = count(*)) AS 连续无洞
FROM agent_message WHERE session_id = '<SID>';
```

| 总条数 | 最小 | 最大 | 连续无洞 |
|---|---|---|---|
| 59 | 1 | 59 | **t** |

跨两个进程、三轮对话、含一次工具调用，**msgSeq 严格 1..59 无洞**（INV-10）。

按角色与类型：

| role | type | 条数 |
|---|---|---|
| USER | TEXT | 3 |
| ASSISTANT | TEXT_DELTA | 51 |
| ASSISTANT | TEXT_END | 3 |
| ASSISTANT | TOOL_CALL | 1 |
| ASSISTANT | TOOL_RESULT | 1 |

长期记忆落在 PG 且按用户隔离：

| namespace | item_key |
|---|---|
| `agents/agent/users/dev/root` | `/MEMORY.md` |
| `agents/agent/users/dev/memory` | `/2026-08-24.md` |
